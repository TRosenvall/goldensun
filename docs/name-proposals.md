# Name proposals — batches 177–179

Hand-written, unlike `docs/names.md`, which is generated by
`tools/name_evidence.py` and must not be edited. This file proposes the
identifiers that generator's `Proposed` column currently leaves as `—` for the
eighteen functions elevated in batches 177–179, and adds the two columns a
rename pass actually needs: which subsystem the function belongs to, and where
it would live under a semantic layout.

## The style these follow

Taken from this tree's own conventions — the named symbols already in `asm/`,
the `Proposed` column of `docs/names.md`, and the module prefixes in use. The
upstream decomp's `src/` was not read.

- `PascalCase`, no underscores, for a plain routine: `GetEquippedItem`,
  `AllocSpriteSlot`, `AdvanceMsgText`, `CanEquipItem`.
- `Subsystem_Verb` where a module owns the function: `Actor_TravelTo`,
  `MapActor_SetIdle`, `Camera_SetTarget`, `ActorCmd_SetAttr`, `UI_SellMenu`,
  `Anim_Judgment`.
- Globals `gState`, `gFlags`; raw regions `iwram_3001e64`, `ewram_2000000`;
  local data labels `.Lb3d40`.
- A near-identical family keeps one base name and is distinguished by what
  actually differs — `Anim_*` by move, `ActorCmd_*` by opcode.

## Read the `Basis` column

Same protocol as `docs/names.md`, and for the same reason: `docs/attribution.md`
records that the inherited annotation corpus gets mechanism right and purpose
wrong often enough to matter.

| Basis | Meaning |
|---|---|
| `read` | behaviour described from the body while elevating it |
| `named` | the ROM annotation proposed an actual identifier |
| `read+callee` | behaviour pinned by reading a callee we had already elevated |

Nothing here is basis `annotation`. Where a name would require knowing something
the code does not say — which status effect a counter belongs to — the row says
so instead of guessing.

## Batch 178 — 10 functions, one family

All ten are `TickStatusCounter` — the ROM's own annotation, and the body agrees:
decrement one per-combatant status counter in the persistent record, return 1 on
the turn it reaches zero, and clear the companion field alongside it. Basis
`named` for the family; `read+callee` for what the roll means, which came from
`Func_80bf208` (already elevated): with five or fewer turns left it rolls
`(luck*3 − turnsLeft*5 + strength) * 0x28f` against `RPGRandom() & 0xffff` and
clears the counter early on success. That callee is worth renaming too —
`RollStatusRecovery`.

**What the evidence does not say** is which status effect each offset is. The
per-effect strength constants (`0x14`, `0x1e`, `0x28`, `0x32`, `0x3c`, `0x46`)
distinguish them numerically and nothing in these bodies names them. The
`Unk<offset>` suffixes below are placeholders that should be resolved from the
status-application side before a rename lands; the offset is the evidence and it
is stable.
