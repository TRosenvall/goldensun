SIGNATURE: TWO PARAMETERS, `(void *context, int variant)`.  `variant` is SPILLED
to sp+0x38 in the second instruction of the body and reloaded at every use
(`ldr r2,[sp,#0x38]`, `ldr r1,[sp,#0x38]`) -- so this one is Nova's spilled
scalar and NOT a register quantity.  `base` is r9 (`mov r9, r1`).  Frame 0x50.
  Mapped slots seen in the prologue and first block: 0x38 variant, 0x34 ctx,
  0x28 g2, 0x24 and 0x20 two derived ints set per variant arm, 0x3c fns[0],
  0x30, 0x18 fp, 0x0c, 0x08; aggregate at sp+0x44.

THE PROLOGUE IS THE FAMILY'S, WITH THE COPY:
  `ldr r2,=iwram_3001eec / mov r3,r2 / ldmia r3!,{r1} / ldr r3,[r3]` then
  `ldr r2,[r2,#8]` for g2 -- so `g` IS kept alive for the indexed read and the
  separate `mov r3,r2` copy is needed.  Spell it
  `g = iwram_3001eec; pp = g; base = *pp++; ctx = *pp; g2 = g[2];`
  (the form that PAID as lever 1 of BaseAnim_Attack's park).  There is no
  `- 0x6c` cam load in the prologue.

*** THE OPENING IS A THREE-ARM VARIANT DISPATCH THAT ALSO CHOOSES THE
AnimStart ARGUMENT, and every arm sets the SAME TWO SLOTS. ***
  variant == 0 : AnimStart(1); sp+0x24 = 0x3c; sp+0x20 = 0x30
  variant == 1 : AnimStart(0); sp+0x24 = 0x3c; sp+0x20 = 0x40
  otherwise    : AnimStart(0); GetBattleActorPos2(slot->f8, &vec);
                 sp+0x24 = vec.x / 2 (signed, the `lsr #31 / add / asr #1`
                 idiom); sp+0x20 = vec.y + 0x30
  The two slots are joined at .Ld4680/.Ld4682 with `str r3,[sp,#0x20]` SHARED by
  all three arms and `str r2,[sp,#0x24]` duplicated per arm.  That asymmetry is
  the BaseAnim_Breath / BaseAnim_Tentacle warning working in the documented
  direction: gcc cross-jumped the tail on its own, so write the two stores in
  each arm and DO NOT hoist either above the `if`.  Tidying the arms to look
  alike is what destroys it.
  Dispatch form: `cmp r2,#0 / bne` then `cmp r1,#1 / bne` on a RELOADED variant,
  with no jump table and no duplicated compare -- an if-CHAIN, like
  ParticleCloud and unlike Breath.

REG_BLDALPHA = 0x1010 IS A WORD POOL (`.Ld46c0 @ 0x1010`, literal `.word
0x1010` in the .s), so BaseAnim_Blob's `int` CARRIER LEVER APPLIES UNCHANGED:
`{ int bld = 0x1010; REG_BLDALPHA = bld; }`.  0x1010 is not
`thumb_shiftable_const` (0x101 > 255), which is WHY the carrier reaches the pool
here and CANNOT on BaseAnim_Attack -- see that park's blocker (A) for the rule.

THE fns[2] TAIL IS THE Attack/Breath SHAPE, with ONE gPtrs pool word held across
both reads:
  `ldr r5,=gPtrs / mov r3,r5 / add r3,#0xb8 / ldr r3,[r3] / str r3,[sp,#0x3c]`
  ... `add r5,#0xbc / ldr r3,[r5] / mov r0,sp / add r0,#0x3c / str r0,[sp,#0x18]
  / str r3,[r0,#4]`
  i.e. `fns[0] = gPtrs[0x2e]; f1 = gPtrs[0x2f]; fp = fns; fp[1] = f1;` -- load f1
  BEFORE `fp = fns`, and use the INDEX form, not `*(DrawFn *)(gPtrs + 0xb8)`,
  because 0xb8/0xbc are past Thumb's `ldr rd,[rn,#imm]` range and gcc emits the
  `add` on its own.  Note this function calls BuildDraw2DFuncEx only TWICE (one
  pair), not eight times as Attack does -- there is no f4 x kind 2x2 here.

*** THE STRUCTURAL KEY: .Lee262 IS A 5-HALFWORD-PER-RECORD TABLE INDEXED BY
slot->f18, AND IT SUPPLIES THE LOOP BOUNDS. ***
  The ROM builds the index as `lsl r3,r2,#2 / add r3,r2 / lsl r3,#1` (that is
  f18*5, in halfwords -> *2 for bytes) and reads TWO entries from each record:
      ((u16 *)Lee262)[f18 * 5 + 1]   -- the `+ 2` byte form, the OUTER gate
                                        (`if (... == 0) goto epilogue`)
      ((u16 *)Lee262)[f18 * 5]       -- the no-offset form, the INNER count
  The inner one is re-read INSIDE the outer loop from a base kept in r4
  (`ldrh r3,[r4,r3]` with `mov r4,r1` hoisted), which is the per-region caching
  the Blob park's lever 4 describes -- ONE `Lee262` base local for the loop
  region, written out longhand at the two uses outside it.
  WRITE `int f5 = f18 * 4 + f18;` AS ITS OWN STATEMENT (the ROM's shape is
  `<<2` then add, NOT a multiply -- do not write `f18 * 5` and let synth_mult
  choose), and index off it.  Batch 306's more-than-one-use precondition is
  satisfied.
