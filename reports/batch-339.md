## The mechanism that did the most work

`allocno_compare` (`global.c:598-620`) scores
`floor_log2(n_refs) * n_refs / live_length`, and **the only source handle on
`live_length` is where a definition sits** — not the order of a block of
definitions, and not declaration order. Three of brief D's four parks had a bound
built on the wrong half:

- `200b51c`'s prose screened six assignment orders and concluded "the lever
  reaches two values, not four". All **24** are flat — right about *order* — but
  moving two definitions to just before their first use **lands it in two lines**.
- `20096a8`'s prose screened *declaration* permutations. Moving `i = 0;` one slot:
  **34 → 22**.

Brief B found the complement: **a value whose uses lie in one basic block is
allocated by `local-alloc`**, so deleting or splitting a reused local can
reassign a callee-saved register no priority lever can reach. `2008f58` landed
byte-identical by **deleting the park's two named locals** — which the park had
explicitly asserted were correct. The tell: removing only one gives 2 of 53.

> That retires `2008f58` from the four-member callee-saved coin-flip grouping,
> and the class bound the other three inherit **gave way twice in one batch by
> two different routes.**

## Brief C on the length gap

- **"Ours shorter means a statement is missing" is right about direction and
  wrong about what to look for.** Three of its four missing instructions were not
  statements: a `pop {r5}` (allocation class), a `mov r12, r3` (one extra
  long-lived value forcing a high register), and a `b` over a literal pool.
- **Count each region separately.** On `80160fc` the net −1 was really **−3
  pre-loop and +2 in-loop** — two mechanisms cancelling in the total.
- **A doc rule needs a precondition.** That park refused a `do`/`while` citing
  "goto loops disable loop optimisation", but the ROM's in-loop pool loads sit
  inside an `if` arm, so `loop.c` declines to hoist them *whatever* the loop form,
  while `step` is unconditional and the ROM **has it hoisted** — which requires
  loop opt ON. A rebuilt loop-invariant is evidence for a `goto` loop **only when
  the rebuild is unconditional**.
- **Deleting a named local added an instruction** (49 → 50), inverting the usual
  rematerialisation rule.
- **An anchor downstream of the residue fixed the residue.** `2008d24`'s park had
  measured six spellings *of the contested call*, all exactly 8, concluding the
  order was "decided below the source". An anchor *after the following call* took
  it to zero, because `INSN_PRIORITY` is computed over the whole basic block.
  **Do not restrict an anchor sweep to the statements around the residue.**
- **`docs/elevation.md:6245` is wrong** and names that exact function.

Brief E added a **third, device-free clause to batch 336's ifcvt table**: reusing
one local for a call's result and the id puts that pseudo in both `MERGE_SET` and
`TEST_LIVE`, so `dead_or_predicable` refuses (`ifcvt.c:1988-1996`). 41 → 4.

## A split attempted and reverted, landing banked

`OvlFunc_951_20096a8` reaches byte-identical but needs `CSE_CFLAGS` and a split.
`split_s.py` refused naming two code labels; those were exported, `make compare`
stayed green, the split succeeded — **and the build failed at link** on
`undefined reference to .L20d0`, a `.lcomm .L20d0, 0x60` local-common (BSS)
symbol declared in one new piece and referenced from the other two.

A `.global` does not fix that; the symbol must become `.comm`, which changes its
binding. Backed out, re-verified at the target SHA1, finding recorded in the park.
`split_s.py` now records the gap: its pre-split check scans `.L` **code-label**
crossings and not `.lcomm`/`.comm` ones.

## Brief A's class

Three of its four targets are **one class with one gate, in the expander**.
`precompute_register_parameters` (`calls.c:849-856`) copies every register
argument whose `rtx_cost(value, SET) > 2` into a pseudo *before* any
hard-register load, its fourth clause unconditionally true in Thumb
(`SMALL_REGISTER_CLASSES` is `TARGET_THUMB`, `arm.h:1061`). So the cheap
`mov r0,#imm` lands last with the highest LUID and sched2's final tie-break
(`haifa-sched.c:4113-4116`) loses it.

The pin-free escape is `local-alloc.c:884-888`, gated on `REG_BASIC_BLOCK < 0` —
**the set and its single use in different basic blocks** — which sharpens that
park's "the branch must be before the site" into a block *boundary* rather than
dominance. None of the three has one, so all hold with pinned recipes recorded.
