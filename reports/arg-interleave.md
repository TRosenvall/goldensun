# Cracking arg-interleave: the basic-block lever

*Not a batch. The record of how a blocker class that stood for 36 batches was
retired, and what the method was.*

## What it was

Two classes, filed separately because their symptoms look unrelated:

    arg-interleave (class 7)    rom  mov r1,#imm / mov r0,#imm / lsl r1,#n
                                ours mov r1,#imm / lsl r1,#n   / mov r0,#imm

    pool-loads-first (class 8)  rom  mov r0, r5 / ldr r1,=X / ldr r2,=Y
                                ours ldr r1,=X / ldr r2,=Y / mov r0, r5

Between them, **1,025 of the 2,966 remaining functions** carry one of these shapes.

## The answer

**The trigger is not at the call site. It is where the value is assigned.**

| the C | what gcc-2.96 does |
|---|---|
| literal at the call site | one piece, contiguous |
| named local, same basic block as the call | held in a callee-saved register |
| named local, **different basic block** | **rematerialised at the call, split** |

Crossing a basic-block boundary stops gcc keeping the value in a register. It
must rebuild it at the call, and its rebuild of a two-instruction constant is
the split pair — with the other argument scheduled into the gap. That is
precisely the ROM's shape.

A **call does not create a boundary**; only a branch does. That is the whole
reason this was invisible: every function anyone had attempted the class on was
straight-line.

## How it was found, and why the previous attempt missed

The class had been worked before. The park note recorded the callee declared,
undeclared and with widened parameters; eight return types on the preceding
callee; seven optimisation flags; `-O1`; and naming the values adjacent to the
call. It concluded **"the C is not the variable."**

Every one of those is a property of the *call site*. The conclusion was right
that the call site is not the variable, and wrong to stop there.

What broke it open was **searching gcc's own output instead of guessing.** The
build leaves generated assembly in `asm/`, so the solved corpus can be scanned
for the pattern directly:

1. Scan every `@ Generated by gcc` file for the interleaved shape. **348 sites.**
   (The earlier investigation had found six, by hand.)
2. Narrow to the exact ROM shape — `mov rA / mov rB / lsl rA`. **33 sites, 31 files.**
3. Separate genuine matches from `// fakematch` files. **Six genuine.**
4. Read those six. Two are on point, and both have the same shape: a shifted
   constant assigned to a named local **early**, used inside or after a
   conditional.
5. Compile five hand-written probes varying one thing at a time to isolate which
   part of that shape is load-bearing.

Step 5 is what turned a correlation into a rule. Probes B and D — named local in
the same block, and a literal inside a conditional — both come out contiguous.
Only the combination interleaves.

**The method is the transferable part.** For any blocker where gcc is known to
emit the wanted shape *somewhere*, the solved corpus is a labelled dataset, and
reading it beats generating variants.

## Later: it defeats constant-CSE too

Found in batch 40, and it is the bigger use.

Where the ROM builds the **same value twice** and gcc builds it once and copies,
giving each occurrence its own named local in a dominating block makes gcc
rematerialise both. That reaches a class this project had written off:

| function | was | now |
|---|---|---|
| `OvlFunc_959_2008ce0` | 6 of 46, two identical shifted constants CSE'd | **matched** |
| `OvlFunc_922_2009750` | **parked**, and a documented counter-example to the `-fno-rerun-cse-after-loop` rule — the flag was byte-identical on it | **matched, no flag** |
| `OvlFunc_968_20087d8` | parked on the `-1` triple, 19 disagreeing | 6, triple solved |

`OvlFunc_922_2009750`'s park had guessed that the CSE flag only reaches values
used as *call arguments* and not values used in *address arithmetic*. That guess
was wrong in a useful way: the discriminator is not what the value is used for,
it is whether the uses sit in a different basic block from the assignment.

**Before reaching for `CSE_CFLAGS`, try separate locals in a dominating block.**
The flag is a build-system change that has to be justified upstream and is
carried in `HANDOFF.md` as a standing question; this is one line of C.

## The limit, stated precisely

**A straight-line function cannot use this.** There is no boundary to put
between the assignment and the call. `OvlFunc_882_20083cc` written this way goes
from two differing instructions to **four** — worse than doing nothing.

Of the 1,025 functions carrying either shape, **516 have a basic-block boundary
before their first site** and 509 are straight-line:

| | functions |
|---|---|
| reachable (a branch before the first site) | **516** |
| straight-line, still parked | 509 |

Of the 509 straight-line ones, 86 are ≤40 instructions, 221 are 41–160, and 202
are over 160.

The four originally-parked arg-interleave members are all straight-line and stay
parked. Their notes now record why, so nobody re-attempts them with this lever.

## What this changes

`reports/large-functions.md` argued that the binding constraint is the number of
unretired blocker classes, not the number of unelevated functions, and that
retiring one class was worth more than hundreds of small elevations.

This is that argument tested. One round, one construct, **516 functions
unblocked** — against a normal round's four.
